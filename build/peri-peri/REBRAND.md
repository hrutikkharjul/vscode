# PeriPeri — VS Code rebrand

This folder contains the brand assets and build helpers for **PeriPeri**, a
chili-pepper themed rebrand of the VS Code source tree.

> **Why fresh GUIDs?** Inno Setup uses `AppId` to identify a product on the
> system. Reusing VS Code's GUIDs would make the PeriPeri installer claim
> ownership of an existing VS Code install and overwrite/uninstall it.

### Icons (`resources/win32/`)

Replaced with a chili-pepper logo generated by `make_logo.py`:

- `code.ico` — multi-resolution ICO containing 16 / 24 / 32 / 48 / 64 / 128 / 256 px frames
- `code_70x70.png` — Windows small tile
- `code_150x150.png` — Windows medium tile

Originals are preserved in `build/peri-peri/backup/win32/`.

### Logo source

- `make_logo.py` — Pillow script that draws the pepper procedurally
- `chili.svg` — hand-written SVG mirror of the bitmap shape
- `chili_1024.png` — master render at 1024×1024

To regenerate after editing `make_logo.py`:

```powershell
python build\peri-peri\make_logo.py
```

## Building the installer

The PowerShell wrapper drives the same gulp pipeline VS Code uses on Azure
Pipelines, minus the code-signing steps.

```powershell
pwsh -ExecutionPolicy Bypass -File build\peri-peri\build-installer.ps1
```

### Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Node.js | 22.x (`.nvmrc` says 22.22.1) | currently `v22.13.1` on this machine — close enough |
| npm | 10.x | bundled with Node |
| Python | 3.x on PATH | for native module gyp builds |
| Visual Studio Build Tools 2022 | "Desktop development with C++" workload | required for `kerberos`, `native-keymap`, `node-pty`, `@vscode/spdlog` |
| Free disk | ~10 GB | for `node_modules` + build artefacts |

Inno Setup itself is **bundled as the npm package `innosetup`** (see
`devDependencies` in `package.json`). You do not need to install it
separately — `npm install` puts `ISCC.exe` under
`node_modules/innosetup/bin/`.

### ⚠️ Required VS components on this machine

A build attempt on this box (2026-05-21) reached a real failure:

```
MSB8040: Spectre-mitigated libraries are required for this project.
```

The native modules VS Code links into the desktop binary
(`@vscode/native-watchdog`, `@vscode/deviceid`, `kerberos`, `node-pty`, etc.)
are compiled with `/Qspectre`. The matching runtime libraries are not part
of the default "Desktop development with C++" workload — they're a
separate Individual Component.

**Install via Visual Studio Installer → Modify → Individual components:**

- `MSVC v143 - VS 2022 C++ x64/x86 build tools (Latest)`
- `MSVC v143 - VS 2022 C++ x64/x86 Spectre-mitigated libs (Latest)`
- `MSVC v143 - VS 2022 C++ ARM64 Spectre-mitigated libs (Latest)` (if building arm64)
- `Windows 11 SDK (10.0.26100.0)` or any recent Windows SDK
- `C++ ATL for latest v143 build tools (x86 & x64)` *(some VS Code modules need ATL)*

After installing, re-run the build script. Two other notes from the same
attempt:

- node-gyp 11 ships with npm 10 has a **PowerShell-based VS detection**
  that fails on this machine even though `vswhere.exe` works. The build
  script works around this by sourcing `vcvars64.bat` before `npm install`.
- The preinstall script enforces Node ≥ 22.22.1 (from `.nvmrc`).
  This box has 22.13.1; the script exports
  `VSCODE_SKIP_NODE_VERSION_CHECK=1` so the install proceeds anyway.

### Pipeline stages (what the script runs)

1. `npm install` — pulls `innosetup`, `electron`, `rcedit`, native modules
2. `npm run gulp core-ci` — compiles, mangles, minifies the core sources
3. `npm run gulp vscode-win32-x64-min-ci` — packages Electron + sources into
   `..\VSCode-win32-x64\` (sibling of the repo)
4. `npm run gulp vscode-win32-x64-inno-updater` — copies `inno_updater.exe`
   and rewrites its embedded icon with `code.ico`
5. `npm run gulp vscode-win32-x64-system-setup` — invokes `ISCC.exe` against
   `build/win32/code.iss` to produce the installer

### Output

The signed Azure pipeline names the installer using `OutputBaseFilename` from
`code.iss`. Without signing, you'll find the unsigned `.exe` in:

```
.build\win32-x64\system-setup\
```

For a per-user installer, run with `-Target user` — the output goes to
`.build\win32-x64\user-setup\`.

### Common failures

- **`gyp ERR! find VS`** during `npm install`
  → Install Visual Studio Build Tools 2022 with the C++ workload.

- **`ENOENT: spawn ISCC.exe`** during the setup task
  → `npm install` did not complete; re-run it. `node_modules/innosetup`
  must exist.

- **`Out of memory`** during compile
  → The gulpfile already passes `--max-old-space-size=8192`. If it still
  OOMs, close other apps; the build wants ~6 GB free RAM.

- **`Cannot find module 'X'`** after a partial `npm install`
  → Delete `node_modules` and re-run `npm install` from a clean state.

## Reverting

To restore the original VS Code branding and icons:

```powershell
Copy-Item build\peri-peri\backup\product.json.bak product.json -Force
Copy-Item build\peri-peri\backup\package.json.bak package.json -Force
Copy-Item build\peri-peri\backup\win32\code.ico.bak resources\win32\code.ico -Force
Copy-Item build\peri-peri\backup\win32\code_70x70.png.bak resources\win32\code_70x70.png -Force
Copy-Item build\peri-peri\backup\win32\code_150x150.png.bak resources\win32\code_150x150.png -Force
```
